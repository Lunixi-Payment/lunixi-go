# Changelog

## 2.0.0 — 2026-11-20

- **Breaking:** the module path is now `github.com/Lunixi-Payment/lunixi-go/v2` (Go major version rule); update the import and `go get github.com/Lunixi-Payment/lunixi-go/v2@v2.0.0`.
- **Breaking — order details required.** Every payment endpoint requires `Buyer` (name, surname, identityNumber, email, gsmNumber, city, country, zipCode, ip), `BillingAddress` (contactName, address, city, country, zipCode) and at least one `BasketItems` entry (id, name, category1, itemType, price); a `PHYSICAL` item also requires `ShippingAddress`. `Payments.CreateIntent`, `Payments.CreateMarketplaceIntent`, `Marketplace.CreateCheckoutIntent`, the marketplace card charges (`ChargeMarketplaceCard`, `ChargeMarketplaceCard2d`, `ChargeMarketplaceCard3d`), `Payments.DirectMethodPayment` and `Payments.Split` return `ErrConfiguration` naming the missing paths (`buyer.email`, `basketItems.0.category1`, `shippingAddress`) before sending; raw `Client.Do` bodies to these routes get the same check. On the checkout intents `buyer.ip` may be left out: the Lunixi form takes it from the browser. `StoreCardRequest` gains `Buyer` and `BillingAddress`, both required for `Payments.StoreCard` (no basket). The `Buyer` type itself does not require `IP`; the endpoint check does.
- New: `OrderDetailsRequiredFields()`, `BuyerRequiredFields()`, `CheckoutIntentBuyerOptionalFields()`, `AddressRequiredFields()`, `BasketItemRequiredFields()`, `OrderFieldErrorCode*` (`payment.order.field_required`, `payment.order.field_invalid`), `OrderFieldReason*`, `OrderDetailsOptions` and `MissingOrderDetails(body, options)` returning the missing paths.
- Split payments take `buyer`, `billingAddress`, `shippingAddress` and `basketItems`; the split body field list `SplitPaymentFields()` includes them and `Split` refuses any other root field before sending.
- Wallet card top-up (`Wallet.Topups.StartCard`) requires `buyer` and `billingAddress` (`shippingAddress` optional); a missing field is refused before sending, and the gateway answers it with 400 `payment.order.field_required` with `details.fields`.
- **Breaking — subscription customers.** `Subscriptions.Customers.Upsert` requires `name`, `surname`, `email`, `gsmNumber`, `identityNumber`, `billingAddress`, `billingCity`, `billingCountry` and `billingZipCode` (renewals take the buyer from this record); `billingContactName` and the shipping fields are optional. `phone`, `locale` and `metadata` are not gateway fields and are refused. New constants `SubscriptionCustomerErrorCodeFieldRequired`, `SubscriptionCustomerErrorCodeFieldInvalid`.
- **Breaking — payment link buyer fields.** `BuyerFieldRequirementHidden` and `BuyerFieldRequirementOptional` are removed; `PaymentLinkBuyerFields` values take only `BuyerFieldRequirementRequired` (the link page always asks all five buyer fields).

- `Payments.DirectMethodPayment(ctx, request, key)` with the `DirectMethodPaymentRequest` builder (`NewDirectMethodPaymentRequest`, `WithMethodFields`, `WithCard`, `WithPromissoryNoteSchedule`, `WithPromissoryNoteCount`, `WithInstallment`, `WithForce3D`, `WithPreauth`, `WithCallbackURL`, `WithLocale`, `WithDescription`, `WithCustomerID`, `WithPaymentChannel`, `WithPaymentGroup`, `WithBuyer`, `WithBillingAddress`, `WithShippingAddress`, `WithBasketItems`, `WithMetadata`, `Body`). Exceptions: `Payments.ListBankTransferExceptions(ctx, BankTransferExceptionFilters)` (environment `TEST` / `LIVE`, status, limit 1–200), `Payments.AcceptBankTransferException`, `Payments.MarkBankTransferExceptionRefunded` (UUID checked locally). Constants `BankTransferExceptionKind*`, `BankTransferExceptionStatus*`, `BankTransferExceptionLimitMax` and the webhook events `PaymentBankTransferEvent*` (`payment.bank_transfer.*`, named apart from Bank Connect transfer events).
- Turkish address dictionary: `Client.Reference.ListProvinces`, `ListDistricts(provinceCode)`, `ListNeighborhoods(districtCode)`.
- Cards: `Payments.BinInfo(ctx, binOrPan)` (digits only, 6–19), `Payments.InstallmentOptions(ctx, InstallmentOptionsRequest)` (amount or intent id; `EnabledInstallments` follows the intent rule and is sent sorted), `Payments.CardTaxonomy`, `Payments.StoreCard(ctx, StoreCardRequest, key)`, `Payments.ListStoredCards`, `Payments.GetStoredCard`, `Payments.DeactivateStoredCard(ctx, token, key)`. ## 1.2.0 — 2026-11-12

- `BasketItem.ProductCategory` (`productCategory`): optional Lunixi product category code, used by payment methods with legal installment limits (e.g. shopping loan) and other platform features. Omitted when empty, so existing requests are unchanged; the API rejects unknown codes with HTTP 400. Codes are exported as `ProductCategory*` constants and `ProductCategories()`; the field stays a string because the dictionary only grows by appending.

## 1.1.0 — 2026-11-04

- `IntentRequest.EnabledInstallments` (`enabledInstallments`): the installment counts the hosted form may offer for one payment (`[]int{1}` = single payment only). It only narrows the panel settings, the card and the platform maximum; nil means no restriction. `CreateIntent` returns `ErrConfiguration` before any request for an empty list, a count outside 1–36, a duplicate or a list without 1, and sends the list in ascending order without changing the caller's slice.

## 1.0.0 — 2026-11-01

- Reject explicit null capture/refund amounts; full remaining operations use omission or the dedicated API described in MIGRATION-1.0.md.

- Breaking: canonical money minor strings in requests and responses; exact decimal currency conversion. See [MIGRATION-1.0.md](MIGRATION-1.0.md).

## 0.1.1 - 2026-10-31

- Provide a concrete merchant-site renderer/example using the existing official Lunixi checkout form by default, with an explicit optional hosted presentation.
- Use only the validated backend paymentPageUrl for redirects; its opaque token is independent of the embedded token. Missing URL keeps embedded available and requires reconciliation for hosted mode without inventing another key.
- Preserve authentication, customer ownership/CSRF integration boundaries, no-store/token-redaction rules and raw response compatibility. Existing published tags are unchanged.

## 0.1.0 — 2026-10-31

- Initial server-side Go SDK with no runtime dependencies.
- Ed25519 PKCS8/seed authentication, JavaScript-compatible canonical JSON, concurrent token cache and bounded signed HTTPS transport.
- Payment lifecycle, split payments, fraud evaluation/events and generic documented merchant API access.
- Integer-money validation, stable keyed retries, redacted errors and preserved response envelopes.
- Raw v2 webhook verification, rotation and transactional PostgreSQL/SQLite replay inbox.
- Runnable TEST checkout and durable SQLite webhook examples, English/Turkish guides, race/security tests and CI.
